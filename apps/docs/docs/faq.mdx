# FAQ

## Where do my skills live?

The **personal library** is `~/.local/share/skl/skills` unless you set `SKL_DATA_DIR`. It is the only directory that `skl sync` reads and writes.

A **project destination** is `.agents/skills` inside a project, created by `skl use`. An **extra destination** is an opted-in directory such as `.claude/skills`. Home agent directories such as `~/.claude/skills` are sources for `skl init`; they are not synchronized.

`skl doctor` prints the resolved config and data paths for this machine.

## Why doesn't `skl use` find a skill that only lives in `~/.claude/skills`?

`skl use` reads only the personal library. Run `skl init` to copy the skill into `~/.local/share/skl/skills`, then run `skl use`.

## I cloned a project with `skills.toml`. Why are the skill directories missing?

`skills.toml` contains only names. Each named skill must exist in this machine's personal library. Log in, run `skl sync`, then run `skl use --all`.

## Why doesn't Cursor need `-a cursor`?

Cursor and Codex already read `.agents/skills`. Use `-a` only for agents with their own project directory, such as Claude Code.

## Why didn't sync change my project?

`skl sync` handles only the personal library. Project directories change when you run `skl use` or `skl use --all`. After syncing on another machine, activate the skills in each project.

## Can the server read my skills?

Yes. Sync uses TLS in transit and stores skill data on the server. It is not end-to-end encrypted. Keep the library local if that does not meet your requirements.

## What does doctor check?

`skl doctor` reports:

- `api_base` and `GET /v1/health`
- Whether a device token is present, and whether `SKL_TOKEN` or `SKL_TOKEN_FILE` is set
- Config and `state.db` paths, writability, and local skill count
- Home skill roots and how many skills each holds
- Whether this machine can create directory symlinks
- `skills.toml` modes in the current project
- Warnings for the old `.claude` / `.cursor` project layout, host-absolute paths in `skills.toml`, and project directories that do not match this machine's library

Doctor does not change files, except that it may show the one-time extras prompt and write its answer.

## Why did Windows copy instead of symlink?

Directory symlinks on Windows require Developer Mode or the `SeCreateSymbolicLink` privilege. If a symlink fails because it is unsupported or not permitted, `skl use` copies the skill and records `mode = "copy"` in `skills.toml`. `skl unuse` removes copies it created. `skl doctor` prints `symlink unavailable` when its check fails.

## How do I update skl?

```bash
skl update
```

That replaces the invoked binary with the latest GitHub Release after checking `SHA256SUMS`. You can also rerun the [install script](/guide/installation).

## The installer did not add PATH

The installer does not edit `.bashrc`, `.zshrc`, or fish configuration. If `~/.local/bin` is not on `PATH`, add `export PATH="$HOME/.local/bin:$PATH"` yourself. The script prints this command when it detects the problem.
