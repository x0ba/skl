# Self hosting

skl is designed for the hosted service. Self-hosting currently requires a source checkout; there is no published application image or Helm chart.

You need Docker for Postgres, Node for `apps/api` and `apps/web`, and a skl binary configured to use your API.

## 1. Postgres

From the repo root:

```bash
docker compose up -d postgres
```

That starts `postgres:16-alpine` on `localhost:5432` with user `skl`, password `skl`, database `skl`.

## 2. API

Use `apps/api/.env.example` as the environment file template.

```bash
cd apps/api
cp .env.example .env
pnpm install
pnpm migrate
pnpm dev
```

The API listens on `http://localhost:8787`. Health is `http://localhost:8787/v1/health`.

Configure these values in `.env`:

- `DATABASE_URL` (default `postgres://skl:skl@localhost:5432/skl`)
- `PORT` (default `8787`)
- `SKL_WEB_ORIGIN` (default `http://localhost:3000`, used for the device URL and CORS)
- `SKL_API_ORIGIN` (default `http://localhost:8787`)
- `CLERK_SECRET_KEY` and related Clerk keys for browser authentication

For local development, leave `CLERK_SECRET_KEY` empty. The API then accepts `Authorization: Bearer dev:<user_id>`.

## 3. Web

The web app serves `/device`, where you approve CLI logins.

```bash
cd apps/web
cp .env.example .env.local
pnpm install
pnpm dev
```

Open `http://localhost:3000`. Device approval is `/device?user_code=…`.

## 4. Point the CLI at your API

```bash
skl --api-base http://localhost:8787 login
```

You can instead set `API_BASE=http://localhost:8787` or `api_base` in `config.toml`. Debug builds already use `http://localhost:8787` by default.

When Clerk is unset on the API, `skl login --dev-user <id>` stores `Authorization: Bearer dev:<id>` and skips device approval. This flag is for local development, not the hosted login flow.

## What you do not get

You operate Postgres, the API, and the web app yourself, including TLS, backups, and Clerk. Anyone with access to the Postgres database can read stored skill blobs.
