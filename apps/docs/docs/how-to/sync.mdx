# Setting up sync

Sync sends the **personal library** through the hosted API. It never changes project directories or home agent directories. You can skip this page if you want to keep the library local.

## Log in

```bash
skl login
```

The CLI prints a verification URL, such as `https://tryskl.fyi/device?user_code=ABCD-2345`, and a user code. Open the URL, approve the device, and wait for the CLI to finish polling.

The **device token** is stored in `~/.local/share/skl/state.db`. Login also writes `api_base` to `~/.config/skl/config.toml`. The OS keyring is not required.

If the code expires, run `skl login` again. If you deny the request, the CLI exits with `device authorization was denied`.

## Second machine

1. Install skl.
2. Run `skl login` and approve the new device.
3. Run `skl sync`.

The second machine downloads the personal library. Each project remains unchanged until you run `skl use` in it.

## Sync

```bash
skl sync
```

`skl sync` uses content hashes to sync only `~/.local/share/skl/skills`. It does not change a project's `.agents/skills` directory or home directories such as `~/.claude/skills` and `~/.cursor/skills`.

You need a local index first. Run `skl init` or `skl create` if `state.db` does not exist yet.

## Conflicts

A conflict occurs when the same skill name has different content locally and on the server. In an interactive terminal, skl prompts for each conflict.

```bash
skl sync --keep-local
skl sync --keep-remote
```

`--keep-local` overwrites the remote skill. `--keep-remote` overwrites the local library copy. skl does not merge conflicts.

In a non-interactive shell, you must pass one of those flags.

## Secret findings

Upload is scanned first. Warning-level findings block the upload unless you pass `--allow-warnings`. Block-level findings always refuse. See [Secret scrubbing](/guide/secrets).

## Auto-sync

When `[sync] auto = true` (the default), login, init, use, unuse, status, create, capture, and list may attempt a background sync. Errors from that sync do not fail the original command. `frequency_secs` defaults to `900`, and failed automatic attempts count toward that interval.

Background sync cannot prompt. On a conflict, it keeps the remote copy. Run `skl sync` directly when you need to choose or use `--keep-local`.

Set `auto = false` to disable automatic sync. `skl sync` still works.

## Log out

```bash
skl logout
```

Logout clears the local device token in `state.db`. It does not revoke the device on the server. Revoke devices on the [devices page](https://www.tryskl.fyi/devices).

## What the server can read

Sync is not end-to-end encrypted. Traffic uses TLS, but the server stores and can read skill blobs. Only sync data you are comfortable providing to that host.
