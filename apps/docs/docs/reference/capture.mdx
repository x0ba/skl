# skl capture

Promote a project skill into the personal library (`~/.local/share/skl/skills`) when the project temporarily won. Day-to-day edits belong in the library (`skl edit`), then `skl use --all`.

## Synopsis

```bash
skl capture <path>
skl capture <path> --force --as <name> --keep-copy --project <dir>
```

## Flags

- `PATH` — project skill path or name, resolved from `.agents/skills` and configured extra directories
- `--force` — overwrite the **canonical library** skill with the same name (rare)
- `--as NAME` — use a different name in the library
- `--keep-copy` — leave the project directory as a real copy
- `--project DIR` — project directory (default: current directory)

Does not prompt.

## What it writes

Copies the source tree to `{data_dir}/skills/<name>/`, indexes it in `state.db`, and adds a name-only entry to `skills.toml`. Unless you pass `--keep-copy`, it replaces the project directory with a symlink to the library copy. It may also start automatic sync.

If the source already symlinks to the library skill, capture only reindexes it.

## Errors

- `capture path is not a skill directory`
- `skill directory … is missing SKILL.md`
- skill already exists in the personal library (needs `--force` or `--as`)
- `skill not found` when the argument is neither a path nor a name in a project skill directory
- `invalid skill name`
- `project skill … already links … but that library skill is missing`
