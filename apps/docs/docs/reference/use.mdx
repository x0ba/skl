# skl use

Make a skill available in a project, list active skills, or refresh all listed skills (`--all`). `skl refresh` is an alias of `skl use --all`.

Edit the library (`skl edit`), then refresh projects. `--force` is only for clobbering unmanaged paths.

## Synopsis

```bash
skl use
skl use <skill>…
skl use --all
skl refresh
skl use --link <skill>
skl use <skill> --project <dir> -a <id>
```

## Flags

- `SKILL…` — skill names. Without names, list skills already active in the project.
- `--all` — rematerialize every skill in `skills.toml` from this machine's library (default: copy). Covers `.agents` and sticky extras already used by the project. Managed projections refresh without `--force`.
- `--link` — symlink instead of copying. Local live-edit only; Cursor Cloud cannot follow `$HOME` links.
- `--force` — clobber an unmanaged real directory or unexpected file. Not required to refresh a symlink or a `mode = "copy"` dest listed in `skills.toml`.
- `--project DIR` — project directory (default: current directory).
- `-a`, `--agent ID` — add an extra agent directory for this activation. Repeatable.

`claude` is accepted as `claude-code`. `cursor` and `codex` cannot be extra destinations because they already use `.agents/skills`.

`--all` cannot be combined with skill names.

Default projection is **copy** (materialize). `project.projection = "link"` in `~/.config/skl/config.toml` makes symlink the default; `--link` still wins on one command.

## What it writes

- Creates `.agents/skills/<name>` as a real directory (copy). `--link` creates a symlink, with a copy fallback if the symlink cannot be created
- Creates extra destinations from `-a` and configured extras
- Updates the project's `skills.toml` (`mode = "copy"` or `mode = "symlink"`)
- May start automatic sync

Does not run `skl migrate`. Does not `git add`.

For Cursor Cloud, commit `.agents/skills/<name>/` and `skills.toml`. See the README section "Using skills with Cursor Cloud agents".

## Errors

- `use either skl use --all or skl use <skill>`
- skill is not in the personal library on this machine
- skill listed in `skills.toml` but not found in the personal library
- dest exists and is not a managed projection (refuses to overwrite a real directory unless `--force`). `--force` on `use` clobbers unmanaged dests; it does not mean overwrite-library (that is `capture --force`)
- invalid skill name (leading `.`, `/`, or `\`)
